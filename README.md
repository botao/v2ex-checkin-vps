# V2EX Check-in VPS

部署在普通 VPS 上的 V2EX 自动签到服务。使用 Playwright 驱动 Chromium，提供响应式管理后台、加密浏览器会话存储、手动签到、执行历史和定时任务。

## 功能

- 后台添加多个 V2EX 账号，不在代码中保存用户名或登录凭据
- 后台内操作 VPS 上的有头 Chromium，登录并核对用户名后保存会话，自动签到不再依赖本机复制的 Cookie
- AES-256-GCM 加密整个数据文件
- Chromium 浏览器访问签到页面（VPS IP 仍可能被 V2EX 要求人机验证，不能保证自动通过）
- 默认每天香港时间 08:10 自动执行
- 记录 V2EX 页面中的实际奖励日期，和本地执行时间分别展示；缺少奖励日期的旧记录显示「未记录」，不按执行日期推算
- 已领取、签到成功、会话失效和浏览器验证分别显示
- PC 和手机后台布局
- 后台任务执行、自动刷新进度，手动请求无需等待所有账号完成
- 全局单任务、账号串行执行，每个账号完成后立即保存记录
- 自动任务遇到明确网络故障或服务器临时错误时，等待 15 秒重试一次，保存两次尝试记录
- 服务重启后将未完成任务标记为已中断，保留已完成的记录
- 收到停止信号后暂停调度、关闭 HTTP 入口，最多等待 75 秒让当前任务完成并保存
- 登录限流、签名会话、CSRF 防护和安全响应头
- Docker 健康检查与持久化数据卷
- 备份工具校验数据与密钥匹配、保留最近 14 份快照，并支持恢复到新目录；Podman 部署提供每日备份定时器
- 初始化命令自动生成随机后台密码及加密密钥，保留已有配置
- 运行环境自检，定位 Chromium 缺失、数据卷权限及密钥不匹配
- 用户名搜索及签到结果筛选，自动刷新时保留筛选条件
- 后台显示下次执行时间、按账号去重的今日完成情况和需处理账号，所有时间跟随配置时区

## VPS 要求

- Linux x86_64 或 arm64
- Docker Engine 24+ 和 Docker Compose v2
- 建议 1 GB 内存、10 GB 磁盘
- 一个能够正常访问 `www.v2ex.com` 的公网 IP
- HTTPS 反向代理，例如 Caddy 或 Nginx

## 部署

```bash
git clone <repository-url> v2ex-checkin-vps
cd v2ex-checkin-vps
```

生成初始配置（使用 Docker，无需在 VPS 上安装 Node.js）：

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD:/workspace" -w /workspace \
  node:22-bookworm-slim node scripts/setup.mjs
```

如果本机已安装 Node.js 22.9+，也可以执行 `npm run setup`。初始化生成随机后台密码和 32 字节加密密钥，写入权限为 `0600` 的 `.env`；重复执行会保留原文件。打开 `.env` 查看 `ADMIN_PASSWORD`，并根据需要修改时区和签到时间：

```ini
ADMIN_PASSWORD=自动生成的后台密码
MASTER_KEY=自动生成的加密密钥
PORT=3000
TZ=Asia/Hong_Kong
CHECKIN_CRON=10 8 * * *
TRUST_PROXY=1
```

上面两项凭据仅为格式说明，不要覆盖初始化生成的真实值。已有数据的服务器必须保留原 `MASTER_KEY`，丢失配置时请恢复备份，不能重新初始化代替旧密钥。

启动：

```bash
docker compose up -d --build
docker compose logs -f app
```

服务默认只监听 VPS 的 `127.0.0.1:3000`。请通过 HTTPS 反向代理访问，不要直接将 3000 端口暴露到公网。

## 环境自检

```bash
docker compose exec app npm run doctor
```

自检会检查配置、数据目录写权限、已有数据能否解密，并实际启动 Chromium 加载一个本地页面。失败时返回非零退出码；不会向 V2EX 发请求，也不会输出密码或 Cookie。该检查通过不代表 VPS IP 一定能通过 V2EX 的人机验证。

直接在本机运行时，先 `npm ci && npm run build`，再执行 `npm run doctor`，它会读取 `.env`。如果提示 Chromium 缺失，请执行 `npx playwright install --with-deps chromium`。

## Caddy 示例

```caddyfile
checkin.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

重载 Caddy 后访问 `https://checkin.example.com`。

## VPS 浏览器登录

所有账号统一使用 VPS 浏览器会话。添加账号后进入登录页；已有账号可直接点击「浏览器登录」，填写 V2EX 用户名、密码和图片验证码并点击「登录」。核对成功后自动保存会话，无需再手动点击保存。已有有效浏览器会话时会直接核对并保存，不必重复输入密码。

页面使用普通 HTML 表单，支持 PC 和手机输入，不再点击截图定位。验证码图片由 VPS 浏览器截图提取；刷新会同时更新原页面的验证码及隐藏令牌，旧验证码版本不能重复提交。密码通过 HTTPS 送到 VPS 浏览器填入原站表单，不自行构造 V2EX 登录请求，不写入配置或日志，提交后清空密码输入框。登录失败需要重新输入密码；两步验证账号会继续显示六位动态码输入框。本入口仅支持 V2EX 站内登录，不支持 Google / Solana 外部登录跳转。遇到无法由表单处理的 Cloudflare 交互验证会明确提示，不尝试绕过。

保存前会重新打开签到页，核对顶部已登录用户名及 A2。未登录、验证码未完成、账号不匹配时不会覆盖已有会话。保存成功后点「签到」验证领取结果；网站拒绝或验证未通过仍报告失败，不绕过验证。

同一进程优先复用同一个浏览器上下文；空闲 10 分钟释放内存，登录窗口最长 20 分钟。浏览器 Cookie、localStorage 和 IndexedDB 加密存入 `store.enc`，重启后用这些状态重建上下文；不持久化整个 Chromium 用户目录、缓存、sessionStorage 或浏览器插件。网站仍可能要求重新登录。

同时只保留一个账号的浏览器上下文。登录期间不对该会话执行自动签到，自动任务会记录需完成登录的提示；请完成登录或取消后重试。取消或登录失败会保留上一次加密会话。切换或删除账号会释放旧上下文，不把不同账号的登录状态混用。每个管理会话每分钟最多提交五次密码／动态码，不自动重试登录。

所有浏览器操作和截图均要求后台登录及 CSRF，限流且不缓存；无公网 CDP/VNC 端口，禁止外部网页导航、下载及 WebSocket。镜像通过 Xvfb 提供虚拟显示，本地 Linux 直接运行时需使用 `xvfb-run -a npm start`，macOS 可直接运行。

现有备份已包含加密浏览器状态，无需新增明文浏览器目录。注意备份文件同时包含 `.env` 中的解密密钥，因此整个备份并非加密归档，须保持现有 root 私有权限，不可公开。

## 旧配置迁移

已移除手动 Cookie 模式，接口不再接受 `cookie` 或 `mode` 配置。启动时自动移除账号中的旧手填 Cookie 和模式字段，保留账号、启用状态、历史记录、任务和已有加密浏览器会话。尚无浏览器会话的账号显示「浏览器 · 待登录」，需完成一次浏览器登录。恢复旧备份后也会执行同样的迁移。

浏览器会话内部的 Cookie 仍是登录状态的一部分，不会清除。不要将登录凭据或会话内容写入源码、Issue 或聊天记录。

## 修改签到时间

`CHECKIN_CRON` 使用标准 5 段 Cron，时区由 `TZ` 控制。例如每天香港时间 08:30：

```ini
TZ=Asia/Hong_Kong
CHECKIN_CRON=30 8 * * *
```

修改后执行：

```bash
docker compose up -d
```

## 更新与回滚

更新：

```bash
git pull --ff-only
docker compose up -d --build
```

回滚到已知提交：

```bash
git switch --detach <commit-sha>
docker compose up -d --build
```

Docker 使用 `checkin-data` 命名卷，避免宿主机目录的权限导致非 root 容器启动失败。业务数据位于容器内 `/app/data/store.enc`。本地直接运行时默认使用 `data/store.enc`。

备份加密数据：

```bash
docker compose cp app:/app/data/store.enc ./store-backup.enc
```

备份时必须同时安全保存 `.env` 中的 `MASTER_KEY`，密钥丢失后数据无法恢复。不要执行 `docker compose down -v`，它会删除数据卷。

Podman VPS 的每日备份部署、校验及恢复流程见 [deploy/README.md](deploy/README.md#daily-backups)。备份同时包含 `.env` 明文密钥，必须按凭据保管，不可提交代码或公开分享。同机备份不能抵御整台 VPS 丢失，需要另外安全保存异地副本。


## 任务执行

点击“签到”或“全部签到”后，服务立即返回任务，后台每 2 秒更新进度；空闲时每 15 秒同步状态。关闭网页不影响正在执行的任务。多个标签页或定时任务同时提交时，只允许一个任务运行，避免同时启动多个浏览器。

今日完成数根据保留的最近 100 条记录，按配置时区及启用账号去重统计；多次签到或重试不会重复增加完成数。最新一次执行失败的启用账号会标记“需处理”，即使该账号今天曾领取成功。停用账号不计入今日完成率或需处理数量。下次执行时间由实际运行中的调度器提供。

“全部签到”和定时任务只处理已启用账号；账号旁的“签到”可单独执行停用账号。任务运行中不能修改或删除账号。编辑时保留已有会话；更换用户名会清除旧会话，需要重新登录。

任务状态和结果保存在同一加密数据文件中。服务重启后不会自动恢复或重试未完成任务，可查看进度后手动再次签到。V2EX 已领取奖励会显示“已领取”，不会重复领取。

自动任务遇到连接中断、导航超时或未包含登录/验证提示的 HTTP 5xx 页面时，会等待 15 秒并最多重试一次。首次失败先保存到历史记录，重试前重新打开每日奖励页面确认领取状态；任务成功/失败统计按账号计数，而不是按尝试次数计数。会话失效、人机验证、HTTP 429、浏览器安装异常或未知页面不会触发自动重试。手动签到不自动重试。

每日奖励页面和领取后的响应均检查 HTTP 状态：401 提示重新登录并保存浏览器会话，403 提示检查访问权限或网络出口，429 明确提示限流且不自动重试。HTTP 错误页即使包含“已领取”文字也不会误判为成功。领取时遇到 5xx 的自动重试仍先访问每日奖励页面确认状态，不直接重复提交领取请求。

V2EX 返回“你的浏览器有一些奇奇怪怪的设置，请用一个干净安装的浏览器重试一下吧”时，会明确显示“浏览器会话被拒绝”，不再显示笼统的“未确认签到成功”，也不会自动重试。这是 V2EX 侧拒绝领取，不代表会话一定失效，不能直接改判签到成功。需要检查该账号的登录和每日奖励页面；重新登录不保证能解除拒绝。

正常停止或更新时，服务会先暂停定时任务、停止接收新请求，再等待当前签到完成并保存结果，最多等待 75 秒。Docker Compose 的停止宽限期应不少于 90 秒；超过等待上限或强制终止后，未完成任务仍会在下次启动时标记为已中断。

## 本地验证

```bash
npm ci
npx playwright install chromium
npm run check
npm run build
npm run setup
npm run doctor
```

开发模式下可设置 `NODE_ENV=development`，此时本地 HTTP 登录 Cookie 不要求 Secure：

```bash
NODE_ENV=development ADMIN_PASSWORD='local-password-123' MASTER_KEY="$(openssl rand -base64 32)" npm run dev
```
